Job Application Automation Pipeline

A pipeline that scans job listings on Jobstreet, scores fit locally with an LLM, and notifies me on Telegram — running unattended, not a one-off script.

Stack Playwright · Ollama (local LLM) · Telegram Bot API
Status Actively running on Jobstreet
Repo github.com/Shoryuuuuuuu/job-automation ↗

How it works

Playwright drives a real browser session against Jobstreet to find and read new listings. Each listing is scored for fit by an LLM running locally through Ollama — no data leaves the machine, no API cost per run. Listings that clear the bar trigger a Telegram notification, so the review step stays in my hands rather than fully auto-applying blind.

What it reports — and what it deliberately doesn't

The dashboard tracks two numbers: total jobs scanned and applications sent. It does not show win rate or interview outcomes. Those depend on employer-side decisions the system has no control over, so surfacing them here would overstate what the pipeline itself is responsible for.

Sentiment Analysis: IndoBERT vs FLAN-T5

Undergraduate thesis comparing fine-tuning against prompt engineering for Indonesian-language sentiment analysis of ride-hailing app reviews.

Methods compared IndoBERT fine-tuning vs. FLAN-T5 (zero-shot, few-shot, Chain-of-Thought)
Data Reviews of Gojek, Grab, and Maxim
Status Completed — pending final defense

Setup

The question was whether prompting a general-purpose model can match a model fine-tuned specifically for Indonesian text. IndoBERT was fine-tuned directly on the review data. FLAN-T5 was tested with three prompting strategies — zero-shot, few-shot, and Chain-of-Thought — with no additional training.

Result, and the honest root cause

Few-shot and Chain-of-Thought prompting underperformed zero-shot — which runs against the usual assumption that more guidance helps. It wasn't a data imbalance issue. Two concrete causes stood out on inspection: the few-shot examples were written in English while the actual inputs were Indonesian, a language mismatch that likely confused the model's pattern-matching; and the output-parsing scheme expected an explicit "Final Answer" marker, which the model often didn't produce within the token limit — so correct reasoning sometimes got scored as a failed parse.
